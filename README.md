# Casco — منصة بناء المواقع بالذكاء الاصطناعي

المستخدم يكتب وصف موقعه بالعربي، فيحصل فوراً على موقع جاهز (صفحة هبوط، متجر، حجز مواعيد، منصة كورسات، منصة إعلانات، أو أي فكرة بقاعدة بيانات ودوال خادم)، ويعدّله بالمحادثة، وينشره — الواجهة والباك إند — على سيرفرات Casco على `slug.casco.studio` أو على دومينه الخاص.

## المكونات

| الجزء | التقنية | المكان |
|---|---|---|
| API + تشغيل المواقع المنشورة | ASP.NET Core 10 (Minimal APIs) + EF Core | `backend/src/Casco.Api` |
| واجهة الـ Builder | React 19 + Vite + Tailwind 4 + lucide-react (عربي / English / हिन्दी) | `frontend/` |
| القوالب | HTML + Tailwind CDN + JS (بدون build) | `backend/src/Casco.Api/SiteTemplates` |
| SDK المواقع (نماذج، تسجيل، كورسات، إعلانات) | JavaScript | `backend/src/Casco.Api/wwwroot/sdk/casco.js` |
| الاختبارات | xUnit | `backend/tests/Casco.Tests` + `scripts/smoke-test.ps1` |
| النشر | Docker + Caddy + PostgreSQL على سيرفرين | `deploy/` |

## التشغيل محلياً

المتطلبات: .NET 10 SDK و Node 22+.

```powershell
# 1) الـ API (على http://localhost:5080) — يستخدم SQLite ووضع AI تجريبي تلقائياً لو مفيش مفاتيح
dotnet run --project backend/src/Casco.Api --launch-profile http

# 2) الواجهة (على http://localhost:5173)
cd frontend
npm install
npm run dev
```

- سجّل بالبريد `admin@casco.local` لتصبح أدمن (لوحة الإدارة `/app/admin`).
- المواقع المنشورة محلياً تفتح على `http://SLUG.localhost:5080`.
- الاختبارات: `dotnet test backend/Casco.slnx` ثم (والـ API شغال) `powershell -File scripts/smoke-test.ps1`.

## لغات الواجهة ولغة المواقع

- **الواجهة:** عربي (RTL) وإنجليزي وهندي (LTR). المستخدم يغيّرها من زر اللغة، وتُحفظ في `localStorage` (`casco_lang`)، ويمكن فرضها بالرابط `?lang=en|ar|hi`. لوحة الإدارة عربي فقط.
- **الترجمة:** النص العربي نفسه هو المفتاح: `t('نص عربي', { n })`، والترجمات في `frontend/src/locales/en.ts` و `hi.ts` (لو المفتاح ناقص يظهر العربي).
- **رسائل السيرفر** (الأخطاء ورسائل التقدم في المحادثة) تُترجم بـ `tServer()`: مطابقة كاملة، أو مفاتيح فيها `{placeholders}` تطابق الرسائل التي فيها أرقام. أي رسالة عربية جديدة في الباك إند تحتاج مفتاحاً في الملفين.
- **لغة الموقع:** عند إنشاء الموقع يختار المستخدم لغته (تلقائي من الوصف، عربي، إنجليزي، هندي، أو أي لغة يكتبها) ويُرسل كـ `language`؛ الموديل يكتب المحتوى بها ويضبط `lang` و `dir` (RTL للعربية والأردية والفارسية والعبرية).

## مفاتيح OpenAI و Gemini و Ziina (لا تضعها في الكود أبداً)

محلياً (تُحفظ خارج المشروع):

```powershell
cd backend/src/Casco.Api
dotnet user-secrets set "Ai:Providers:openai:ApiKey" "sk-..."
dotnet user-secrets set "Ai:Providers:gemini:ApiKey" "AIza..."
dotnet user-secrets set "Ziina:ApiKey" "..."
dotnet user-secrets set "Ziina:WebhookSecret" "نص-عشوائي-طويل"
```

على السيرفر: في ملف `deploy/server1/.env` (مثال في `.env.example`).
بمجرد إضافة أي مفتاح يتوقف الوضع التجريبي ويبدأ استخدام الموديلات الحقيقية.
لتشغيل `smoke-test.ps1` بدون تكلفة شغّل الـ API على الموديل التجريبي: `$env:Ai__UseFake="true"; dotnet run`.

## تسجيل الدخول بـ Google و Apple و Cloudflare

```powershell
dotnet user-secrets set "Auth:Google:ClientIds" "xxxx.apps.googleusercontent.com"
dotnet user-secrets set "Auth:Apple:ClientIds" "com.example.web"          # Services ID للويب
dotnet user-secrets set "Storage:R2:ServiceUrl" "https://ACCOUNT_ID.r2.cloudflarestorage.com"
dotnet user-secrets set "Storage:R2:BucketName" "..."
dotnet user-secrets set "Storage:R2:AccessKey" "..."
dotnet user-secrets set "Storage:R2:SecretKey" "..."
```

- **Google**: في Google Cloud Console أضف `http://localhost:5173` ودومين Casco إلى *Authorized JavaScript origins*. الـ Client Secret غير مطلوب (نتحقق من الـ ID token مباشرة).
- **Apple**: في Services ID أضف دومين Casco و `https://DOMAIN/login` كـ Return URL. Apple لا يقبل localhost، فيُجرب على الدومين الحقيقي فقط.
- **Turnstile**: محلياً نستخدم مفاتيح Cloudflare التجريبية (تنجح دائماً). على السيرفر ضع مفاتيحك وأضف دومين Casco لقائمة hostnames في الـ widget.
- **R2**: محلياً الصور تُحفظ على القرص (`Storage:Provider=Local`). على السيرفر `Storage:Provider=R2` مع `Storage:R2:PublicUrl` (دومين عام للبكت مثل `https://cdn.casco.studio`). ساعتها صور وفيديوهات وملفات مواقع العملاء والمنتجات تتحمل من كلاودفلير مباشرة، والرابط القديم `/u/...` بيعمل تحويل للدومين ده. الـ token يحتاج صلاحية *Object Read & Write*، ولازم تفعيل Public access وربط الدومين من إعدادات البكت.

## الموديلات وخطة التبديل

كل طلب يمر على "مستوى" (tier)، ولكل مستوى سلسلة موديلات: الأول أساسي والباقي احتياطي تلقائي لو فشل.

| المستوى | يُستخدم في | الافتراضي |
|---|---|---|
| `cheap` | الخطة المجانية | `gpt-6-luna` ← `gemini-3.1-flash-lite` |
| `standard` | مشتركي Pro | `gpt-6-luna` ← `gemini-3.5-flash` |
| `premium` | "الوضع القوي" (Pro فقط) | `gpt-6-sol` ← `gemini-3.5-flash` |

- **التبديل الفوري:** من لوحة الإدارة ← "تبديل الموديلات" (ترتيب/إضافة/حذف) بدون إعادة تشغيل. زر "استرجاع الافتراضي" يرجع لإعدادات `appsettings.json`.
- **إضافة موديل جديد:** أضفه في `Ai:Models` داخل `appsettings.json` (المعرّف، المزود، الأسعار لكل مليون توكن) ثم اختره من لوحة الإدارة.
- **مهم:** راجع أسماء الموديلات وأسعارها الحالية في صفحات أسعار OpenAI و Google قبل الإطلاق وعدّلها في `appsettings.json`، لأن حساب النقاط يعتمد على هذه الأسعار.

## كيف نقلل تكلفة الذكاء الاصطناعي

1. **موديلات رخيصة افتراضياً** والقوي فقط عند الطلب ولمشتركي Pro.
2. **كاش الردود المحلي:** أي طلب مطابق تماماً يُرد من قاعدة البيانات بتكلفة صفر (7 أيام).
3. **Prompt caching عند المزود:** الرسالة مرتبة بحيث الجزء الثابت (التعليمات + القالب) يأتي أولاً، ومفتاح `prompt_cache_key` ثابت لكل قالب/مشروع، فتُحتسب التوكنز المتكررة بسعر الكاش (أرخص ~90%).
4. **تعديلات بالـ diff:** الموديل يرجع "ابحث/استبدل" بدل إعادة كتابة الملف كاملاً ← توكنز خرج أقل.
5. **حجز نقاط + Kill switch:** كل مهمة لها حد أقصى، ولا تتجاوز تكلفتها ما حُجز لها.
6. **حدود:** معدل طلبات لكل مستخدم، 3 محاولات إصلاح كحد أقصى لكل جزء من الطلب، وحجم سياق محدود. `Agent:Workers` = 8 مهام متوازية (نداءات AI تنتظر الشبكة، والطلب الكبير يشغل عاملاً لعدة دقائق).

متابعة التكلفة: لوحة الإدارة تعرض التكلفة لكل موديل، ونسبة الـ prompt cache، وعدد ردود الكاش المجانية.

### تكلفة كل عملية AI (اقتصاديات المستخدم)

- كل نداء لمزود AI يُسجَّل في جدول `AiUsages` (حتى الفاشل والـ fallback وجولات الإصلاح وردود الكاش): `UserId, ProjectId, TaskId, Provider, Model, Purpose, Plan, InputTokens, CachedInputTokens, OutputTokens, EstimatedCostUsd, ActualCostUsd, DurationMs, RetryCount, Success, Error, CreatedAt`.
- **EstimatedCost** = التوكنز التي أرجعها المزود × جدول الأسعار (وعليه تُخصم النقاط). توكنز التفكير المخفية (Gemini) تُحسب ضمن المخرجات، والنداء الذي انقطع أو انتهى وقته يُسجَّل بتكلفة تقديرية لأن المزود يحاسب عليه.
- **ActualCost** = التكلفة التي أرجعها المزود نفسه إن وُجدت، وصفر لردود الكاش، وإلا تُملأ من الفاتورة الشهرية.
- **كل شهر:** من لوحة الإدارة ← "اقتصاديات المستخدم" ← "مطابقة الفاتورة"، اختر المزود واكتب مبلغ فاتورته. يتم توزيع الفرق على كل النداءات بنفس النسبة، فتصبح تكلفة كل مستخدم/مشروع/مهمة مطابقة للفاتورة.
- التقرير (`GET /api/admin/economics?month=yyyy-MM`) يجيب: متوسط/وسيط/p90 تكلفة المستخدم النشط، مجاني مقابل Pro، هامش Pro بعد رسوم الدفع وتكلفة المستخدمين المجانيين، تكلفة كل تسجيل جديد، هامش الاستضافة مقابل مصاريف التطبيق للموقع، والتوزيع حسب الغرض والموديل والمزود.
- مصاريف التطبيق (سيرفرات، دومين، بريد، أي بند تسمّيه) تُضبط من لوحة الإدارة ← الأسعار. `Billing__Economics__PaymentFeePercent` لنسبة رسوم الدفع.
- **تكلفة الموقع كاملاً:** المشروع ← المهام ← الأجزاء (`AiUsages.Part`). التقرير فيه: توزيع تكلفة الطلب الواحد وشرائحها، الطلبات متعددة الأجزاء، أغلى الطلبات والمواقع، وهامش كل مشترك Pro (الإيراد − AI − التخزين/الاستضافة) مع شرائح تكلفة AI وعدد أصحاب الهامش السالب.

### صحة النظام واختبارات الحمل والجودة

- `GET /api/admin/system?minutes=60` (وبطاقة "صحة النظام" في لوحة الإدارة، تتحدث كل 10 ثوانٍ): CPU و RAM للعملية، المهام الجارية/في الانتظار/الفاشلة، متوسط و p90 زمن التوليد وانتظار الطابور، زمن استجابة الـ AI وعدد 429، اتصالات PostgreSQL، المساحة الحرة، والنقاط المحجوزة حالياً.
- **اختبار الحمل:** `powershell -File scripts/load-test.ps1 -Base https://staging... -Users 8` يسجل 8 مستخدمين Pro ويبدأ 8 بناءات كبيرة في نفس اللحظة ويسجل كل 3 ثوانٍ، ثم جدول لكل مستخدم + ملخص القمم في `scripts/out/`. افتراضياً يستخدم الموديل التجريبي (`#demo-pages-16 #demo-slow-3` = 8 أجزاء بتأخير 3 ثوانٍ لكل نداء)؛ مرر `-Prompt "..."` لطلب حقيقي.
- **تقييم الجودة بموديل حقيقي (يكلف):** `powershell -File scripts/eval-prompts.ps1 -Base https://staging...` يشغل الـ 10 سيناريوهات في `scripts/eval-prompts.json` (Landing، مطعم، Portfolio، كورسات، عقارات، عيادة، متجر، إعلانات، شركة، RTL): توليد ← معاينة ← RTL ← 5 تعديلات (منها فحص اسم الشركة في كل الصفحات، صفحة جديدة تستخدم الـ layout، تغيير لون القائمة في ≤3 ملفات) ← تراجع ← نشر ← التكلفة، ويكتب جدول markdown بروابط المعاينة؛ عمود "Visual" تملأه يدوياً. `-Only "landing,store"` لتشغيل بعضها.
- السكربتان يسجلان مستخدمين جدد، فيحتاجان سيرفر بمفاتيح Turnstile التجريبية (Development أو staging) — لا تشغلهما على الإنتاج.
- علامات الموديل التجريبي: `#demo-pages-N` (طلب كبير على أجزاء)، `#demo-slow-N` (تأخير N ثانية لكل نداء)، `#demo-flaky` (أول نداءين يرجعان 429).

## الخطط والنقاط

- **مجاني:** موقع واحد (صفحة واحدة: تعريفي أو متجر أو حجوزات). **أول توليد مجاني دائماً**، وحتى لو فشل الموديل يبقى للمستخدم موقع جاهز من القالب. المعاينة مجانية، والتعديل بالذكاء الاصطناعي يحتاج Pro.
- **Pro:** ‎$18 شهرياً أو ‎$180 سنوياً — التعديل بالكلام، 5000 نقطة شهرياً (السنوي أيضاً يُشحن شهرياً)، مواقع متعددة الصفحات (حد تقني في الإعدادات)، كورسات/إعلانات، بدون شعار Casco، تحميل ZIP. النقاط حسب حجم الموقع وقد لا تكفي لبناء موقع كبير كامل.
- **حجم الموقع:** المجاني 30 ملف / 1MB. Pro حتى 200 ملف / 5MB (`Agent:ProMaxFiles` و `Agent:ProMaxTotalBytes`)، وأقصى حجم للملف الواحد 200KB.
- **الطلبات الكبيرة (Pro):** رد الموديل الواحد يكفي 3–4 صفحات تقريباً، فلو الطلب أكبر يرجع الموديل ما تبقى في `remaining` ويكمل الوكيل تلقائياً على أجزاء (حتى `Agent:MaxStepsPerTask` = 8 أجزاء في الطلب الواحد، كلها في نسخة واحدة). الحجز يُمدَّد من رصيد المستخدم مع كل جزء؛ لو خلص الرصيد أو وصل لحد الأجزاء أو حصل خطأ مؤقت، يُحفظ كل ما تم بناؤه وتظهر للمستخدم رسالة تقدم ("تم إنشاء 16 من 30 صفحة، وتبقى 14") وزر **«كمل البناء»** في المحرر (أو يكتب «كمل»)، فيُكمل الوكيل الطلب الأصلي من حيث توقف (`POST /api/projects/{id}/messages` بـ `{ "continue": true }`). لو وصل الموقع لحد الملفات/الحجم يتوقف فوراً برسالة واضحة بدل جولات إصلاح.
- **كل جزء ذري:** الجزء يُطبق ويُتحقق منه في الذاكرة ثم يُحفظ كـ checkpoint على المهمة (`AgentTask.CheckpointJson`) قبل بدء الجزء التالي. لو انقطع جزء في منتصفه يُتجاهل بالكامل (لا يُحفظ نصف جزء). لو السيرفر وقع أثناء البناء، عند التشغيل (وكل `Agent:ReconcileMinutes` = دقيقتين) تُكتشف المهام الميتة: ما له checkpoint يُحفظ كنسخة ويُحاسب المستخدم على الأجزاء المكتملة فقط ويظهر له «كمل البناء»، وما ليس له يفشل بدون خصم.
- **حالات النقاط:** كل حجز يبقى سجلاً: `reserved` (محجوز) ← `settled` (استُهلك، مع `Consumed`) أو `released` (أُطلق، مع السبب: completed / failed / free / restart / stale). لا يُخصم شيء قبل النتيجة، فالفشل = إطلاق الحجز (لا يوجد استرداد منفصل). مهمة الـ reconciliation تطلق أي حجز مهمته انتهت أو ماتت.
- **أخطاء المزود المؤقتة (429/5xx):** نفس الموديل يُعاد بـ exponential backoff + jitter (سقف 1/2/4/8 ثوانٍ، `Agent:ProviderRetries` = 4، ويحترم `Retry-After` حتى 20 ثانية) ثم ينتقل للموديل التالي. الإعادة ليست مهمة جديدة ولا تُخصم؛ النداءات الفاشلة تُسجل بتكلفة 0.
- **الـ layout المشترك:** في المواقع متعددة الصفحات الهيدر/القائمة/الشعار/الفوتر في `assets/layout.js` فقط، والـ validator يرفض أي صفحة لا تحمّله؛ فتغيير اسم الشركة أو لون القائمة = تعديل ملف واحد.
- **النسخ:** يُحتفظ بآخر 50 نسخة لكل موقع (`Agent:KeepVersions`)، ولا تُحذف أبداً النسخة الحالية أو المنشورة. كل نسخة تحفظ: الرقم، الطلب (Prompt)، من أنشأها، الوقت، الموديل، عدد الأجزاء، عدد الملفات المتغيرة (تظهر في نافذة النسخ).
- **استضافة لكل موقع (منفصلة عن Pro):** ‎$5 شهرياً لموقع واجهة فقط (صفحات + نموذج تواصل)، و ‎$10 شهرياً لو الموقع فيه باك إند (حسابات، قاعدة بيانات، متجر، حجوزات، كورسات، إعلانات، دوال خادم). السنوي = 10 شهور.
  - Casco يحدد النوع تلقائياً من كود الموقع؛ النشر وربط الدومين يحتاجان استضافة فعالة.
  - بعد انتهاء المدة بـ 3 أيام سماح يتوقف الموقع (والباك إند يرد `backend_inactive`). قبل النشر يعمل الباك إند في وضع تجربة بحد 25 عنصر.
  - الأدمن يقدر يفعّل استضافة يدوياً: `POST /api/admin/projects/{id}/hosting` بـ `{ "tier": "static" | "backend", "months": 1, "amount": 10 }` (`amount` اختياري: المبلغ المستلم بالتحويل أو الكاش ويُسجَّل كدفعة).
- **كل الأسعار والحدود أعلاه قابلة للتعديل من لوحة الإدارة ← "الأسعار"** (تُحفظ في قاعدة البيانات وتطبق فوراً بدون إعادة تشغيل؛ القيم في `appsettings.json` هي الافتراضية وزر "استرجاع الافتراضي" يرجع لها). التغيير يؤثر على المدفوعات الجديدة فقط.

## لوحة الإدارة

- **نظرة عامة:** إحصائيات 30 يوم + اقتصاديات المستخدم (تكلفة AI لكل مستخدم وهامش Pro).
- **المستخدمون والمواقع:** فلاتر بعدد كل فئة: الكل، بنوا موقع، دفعوا، **بنوا ولم يدفعوا**، لم يدفعوا، بدون موقع، مشتركين Pro، مواقعهم متوقفة، موقوفين إدارياً. بحث بالبريد أو الاسم أو اسم الموقع أو الدومين، وترتيب بآخر نشاط أو الأكثر دفعاً أو الأعلى تكلفة.
  - صفحة كل مستخدم: كل مواقعه (رابط الموقع المنشور + معاينة آخر نسخة حتى لو غير منشور + حالة الاستضافة ونوعها المطلوب)، كل مدفوعاته (مكتملة وغير مكتملة)، النقاط وتكلفة AI عليه.
  - تفعيل Pro أو استضافة أو إضافة نقاط يدوياً مع كتابة المبلغ المستلم (تحويل/كاش) فيُحسب في الإيراد و"دفعوا". مبلغ 0 = هدية.
  - "دفع" = عنده دفعة مكتملة حقيقية (Ziina أو يدوية)؛ مدفوعات وضع الاختبار لا تُحسب.
  - **إيقاف موقع إدارياً** (زر "إيقاف الموقع" مع سبب إجباري، وفلتر "موقوفين إدارياً"): قرار مستقل عن الدفع ومخزّن في `IsAdminSuspended / AdminSuspensionReason / AdminSuspendedAt / AdminSuspendedBy`.
    - الأولوية: موقوف إدارياً ← انتهت الاستضافة وأيام السماح ← يعمل. الإيقاف يغلب حتى لو الاستضافة مدفوعة.
    - الزوار يرون "الموقع متوقف مؤقتاً" وكل الـ API العام للموقع يرد `403 site_suspended` (حتى في المعاينة) بدون ذكر السبب.
    - صاحب الموقع يرى السبب ورقم الدعم في المحرر، ولا يستطيع النشر أو دفع استضافة للموقع حتى يُلغى الإيقاف.
    - `HostingPaidUntil` لا يتغير، وإلغاء الإيقاف يرجع الموقع لحالة استضافته كما هي (لو انتهت يبقى متوقفاً).
    - API: `POST /api/admin/projects/{id}/suspend` بـ `{ "reason": "..." }` و `POST /api/admin/projects/{id}/unsuspend`.
- **الأسعار:** سعر Pro الشهري/السنوي ونقاطه وعدد مواقعه، الخطة المجانية، أسعار الاستضافة وأيام السماح، باقات الشحن، قيمة النقطة، تكلفة السيرفرات ورسوم الدفع — مع حساب فوري لتكلفة AI القصوى والصافي لكل سعر.
- **الموديلات:** ترتيب الموديلات لكل مستوى.
  - **المواقع المنشورة قبل هذا التحديث تحتاج تفعيل استضافة** (يدوياً من الأدمن أو بالدفع) وإلا تتوقف.
- **شحن نقاط:** 2000 نقطة بـ ‎$5، و 5000 بـ ‎$10 (لا تنتهي).
- النقطة = ‎$0.001 من التكلفة الفعلية. تُعدّل كل القيم من قسم `Billing` في `appsettings.json`.

## Ziina

- ⚠️ **الحساب الشخصي في Ziina لا يسمح قانونياً بقبول مدفوعات تجارية**؛ يجب الترقية إلى حساب Business قبل استقبال مدفوعات حقيقية. حتى ذلك الوقت يمكن تفعيل الاشتراك يدوياً من لوحة الإدارة (زر "تفعيل Pro") بعد استلام الدفع بأي وسيلة.
- Ziina لا يدعم الاشتراكات المتكررة، لذلك كل دفعة تشتري شهراً أو سنة، والتجديد المبكر يُضاف للمدة الحالية، ويظهر للمستخدم تنبيه قبل الانتهاء بـ 5 أيام.
- خطوات التفعيل: ضع `Ziina__ApiKey` و `Ziina__WebhookSecret`، اترك `Ziina__TestMode=true` للتجربة، ثم من لوحة الإدارة اضغط "تسجيل Webhook لـ Ziina". عند الجاهزية اجعل `Ziina__TestMode=false`.
- الأمان: يتم التحقق من توقيع الـ webhook، ودائماً نعيد جلب حالة الدفع من Ziina قبل التفعيل، والتفعيل لا يتكرر لنفس الدفعة.

## النشر على سيرفرين Contabo

**Cloudflare Pages:** الواجهة (`casco.studio`).
**السيرفر 1:** Caddy + الـ API على `api.casco.studio` (المعاينة + كل المواقع المنشورة + الملفات المرفوعة + `sdk/casco.js`).
**السيرفر 2:** PostgreSQL + نسخ احتياطي يومي.

### الواجهة على Cloudflare Pages

- Workers & Pages ← Create ← Pages ← اربط الـ repo (أو ارفع مجلد `dist` يدوياً).
- Root directory: `frontend` — Build command: `npm run build` — Output: `dist`.
- Environment variable (Production): `VITE_API_URL=https://api.casco.studio` (بدونه الواجهة تكلم نفس الدومين).
- Custom domains: `casco.studio` و `www.casco.studio`.
- لا يوجد `404.html`، فـ Pages يعاملها كـ SPA تلقائياً (`/login` و `/app/...` تفتح `index.html`).
- لو فتحت preview deployment (`*.pages.dev`) أضف رابطه إلى `App__CorsOrigins__N` وإلا طلبات الـ API ترفض.
- لو فتح أحد صفحة من الواجهة على `api.casco.studio` يُحوَّل إلى `casco.studio`.

### Cloudflare (DNS)

الواجهة على `casco.studio`، والـ API على `api.casco.studio`، وكل موقع منشور على `اسم-يختاره-العميل.casco.studio` (العميل يكتب الاسم عند أول نشر، ويغيّره من إعدادات الموقع).

| السجل (Name) | النوع | القيمة | Proxy |
|---|---|---|---|
| `@` و `www` | يضيفهم Pages تلقائياً عند ربط الـ Custom domain | — | برتقالي |
| `api` | A | IP السيرفر 1 | برتقالي (Proxied) |
| `*` (كل المواقع) | A | IP السيرفر 1 | برتقالي (Proxied) |
| `sites` | A | IP السيرفر 1 | رمادي (DNS only) — هدف CNAME للدومينات الخاصة |

- SSL/TLS ← Overview ← **Full (strict)**.
- SSL/TLS ← Edge Certificates: شهادة Universal SSL المجانية تغطي `casco.studio` و `*.casco.studio` تلقائياً (مستوى واحد فقط، لذلك روابط المواقع `name.casco.studio` وليس `a.b.casco.studio`).
- SSL/TLS ← Origin Server ← **Create Certificate** يغطي `casco.studio, *.casco.studio`، واحفظه على السيرفر 1 في `deploy/server1/certs/origin.pem` و `origin.key`.
- الدومينات الخاصة للعملاء (CNAME إلى `sites.casco.studio`) تأخذ شهادة Let's Encrypt تلقائياً من Caddy، لذلك سجل `sites` يجب أن يبقى رمادي.
- الفيديوهات: ارفعها على YouTube (غير مدرج) أو Bunny Stream وضع الرابط في الدرس، لا تُخزّن على السيرفر.

### السيرفر 2 (قاعدة البيانات)

```bash
apt update && apt install -y docker.io docker-compose-v2 openssl
git clone <repo> /opt/casco && cd /opt/casco/deploy/server2
cp .env.example .env && nano .env                 # كلمة سر قوية
sed -i "s/SERVER1_IP/<IP السيرفر 1>/" pg_hba.conf
mkdir -p certs backups
openssl req -new -x509 -days 3650 -nodes -subj "/CN=casco-db" -keyout certs/server.key -out certs/server.crt
chown 70:70 certs/server.key certs/server.crt && chmod 600 certs/server.key
docker compose up -d
```

## الإيميلات والمراقبة وسجل الأخطاء

كل الإيميلات تخرج من `no-reply@casco.studio` بقالب موحد (اللوجو، ألوان حسب نوع الرسالة، متجاوب مع الموبايل، RTL للعربي) وبلغة واجهة المستخدم (عربي / English / हिन्दी).

**لك (صاحب المنصة) على `Monitor__AlertEmails`:** السيرفران يُفحصان كل دقيقة:

| المقياس | تحذير | خطر |
|---|---|---|
| CPU (3 دقائق متواصلة) | 85% | 95% |
| الرام (3 دقائق متواصلة) | 90% | 95% |
| القرص | 85% | 95% |
| اتصالات قاعدة البيانات | 80% | 95% |
| الأخطاء في آخر 10 دقائق | 20 | 100 |
| السيرفر 2 لم يرسل بياناته | — | 5 دقائق |
| قاعدة البيانات لا ترد / Postgres متوقف | — | فوراً |
| عمر آخر نسخة احتياطية | 26 ساعة | 52 ساعة |

يصل إيميل عند الوصول للحد، وتذكير كل 6 ساعات لو المشكلة مستمرة، وإيميل "رجعت طبيعية" عند الحل، ومع كل تنبيه جدول بكل القراءات وخطوات الحل. الحدود قابلة للتعديل من `.env` (`Monitor__Disk__Warning=80` مثلاً).

**للمستخدمين تلقائياً:** تذكير قبل انتهاء Pro بـ 7 أيام ويوم، ورسالة عند الانتهاء؛ تذكير قبل انتهاء استضافة كل موقع بـ 7 أيام ويوم، ورسالة في فترة السماح، ورسالة عند توقف الموقع (الزر يفتح نافذة التجديد مباشرة)؛ إيصال بعد كل دفعة؛ تنبيه عند نزول النقاط تحت 10%؛ وإشعار لصاحب الموقع بكل طلب/حجز/رسالة. كل رسالة تُرسل مرة واحدة فقط.

**التفعيل:**
1. اختر مزود SMTP (مثلاً [Resend](https://resend.com) أو [Brevo](https://www.brevo.com) أو Amazon SES) وأضف الدومين `casco.studio` عنده.
2. في Cloudflare ← DNS أضف السجلات التي يعطيها المزود بالضبط (كلها **رمادي / DNS only**): سجل SPF (TXT)، وسجلات DKIM، وسجل DMARC مثل `_dmarc` TXT `v=DMARC1; p=quarantine; rua=mailto:nasermostafa.ma122@gmail.com`. بدونها تذهب الرسائل للـ Spam.
3. على السيرفر 1 في `.env`: `Smtp__Host` و `Smtp__User` و `Smtp__Password` (منفذ 587)، و `Monitor__AgentToken` (قيمة عشوائية: `openssl rand -hex 32`).
4. على السيرفر 2 في `.env`: `MONITOR_TOKEN` بنفس القيمة و `MONITOR_URL=https://api.casco.studio/api/internal/metrics`، ثم `docker compose up -d`.
5. من لوحة الإدارة ← النظرة العامة ← "مراقبة السيرفرين" اضغط **إيميل تجريبي**: يصلك نموذج من كل رسالة، ومن نفس المكان تقدر تعاين كل القوالب بالثلاث لغات.
6. لو السيرفر 1 نفسه وقع لن يستطيع إرسال شيء، لذلك أضف فحصاً خارجياً مجانياً (مثل UptimeRobot) على `https://casco.studio/health` يرسل لنفس الإيميل.
7. لو فعّلت Bot Fight Mode أو WAF في Cloudflare استثنِ المسار `/api/internal/metrics`.

**سجل الأخطاء:** كل التحذيرات والأخطاء تُكتب في `deploy/server1/data/logs/casco-YYYY-MM-DD.log` (تُحذف بعد 30 يوماً)، وآخر 50 خطأ تظهر في لوحة الإدارة مع التفاصيل. سجلات Docker محدودة الحجم على السيرفرين. في التطوير تُحفظ الإيميلات كملفات `.eml` في `backend/src/Casco.Api/data/mail` بدل إرسالها.
